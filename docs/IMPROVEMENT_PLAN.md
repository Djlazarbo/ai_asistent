# Job Hunter — общий план улучшений (v3, 22.11.2026)

Один источник правды по развитию бота. **Стержень (тезис владельца): бот работает для каждого человека — его вакансии, его хотелки, его опыт.** Всё ниже подчинено этому.

**Точка старта:** прод 1.2.2 (изоляция лент, неблокирующий поиск, tg_notify, SSH/ufw hardening). Тесты: 354 unit, зелёные. Жалоба-драйвер: «вакансии не очень мониторятся у пользователей» + «поиск работает криво».

**Правила (неизменны):** одна БД, изоляция через `user_*`-таблицы · никаких глобальных фильтров/порога/опыта hh — только per-user · не ломать non-PM роли (маркетинг/безопасность) · секреты не коммитить · деплой на прод — с подтверждением владельца.

---

## 0. Профиль хотелок — стержень персонализации (P0)

Каждый юзер получает экран **«Мои хотелки»**, и ВСЕ этапы пайплайна обязаны их соблюдать.

### 0.1 Карта «уже персонально / всё ещё общее» (прод 1.2.2)

| Этап | Уже per-user ✅ | Всё ещё глобально/общее ❌ |
|------|----------------|---------------------------|
| Настройки поиска | keywords, TG-каналы, резюме, salary_from | опыт hh, формат (удалка/офис/гибрид), регион — 8 одинаковых конфигов для всех |
| Фильтры инжеста | companies_block/want (на fan-out) | junk-фильтр (dev/маркетинг/др.) вырезает из ОБЩЕГО пула; NOT-исключения PM-запроса для всех |
| Сам поиск | «Искать сейчас» по своим словам | daily-крон 09:00 — одна boolean-команда по union всех юзеров; PM ищет только по NAME: |
| Скоринг | профиль в промпте DeepSeek, личный порог | хотелки (зарплатная вилка, формат, опыт) в промпт не идут |
| Доставка | notify/ears_freq/quiet hours, личный порог | время daily-дайджеста одно на всех (ключ digest_time пишется, не используется) |
| Лента | user_vacancies, backfill по своим словам/каналам | backfill только после своего «Искать сейчас» (нет периодического) |

### 0.2 Состав профиля хотелок (`user_settings`, без миграций схемы)

- `wish_role` — роль/роли (дефолт: из резюме, редактируется)
- `wish_salary_min` / `wish_salary_max` — вилка (легализует нынешний `salary_from`)
- `wish_format` — remote | office | hybrid | any
- `wish_experience` — 1–3 | 3–6 | 6+ | any (пер-юзерный опыт hh из TASKS.md становится явной хотелкой)
- `wish_location` — Москва | СПб | … | любой
- `wish_exclude` — личные «не показывать» (роли/слова), действуют на fan-out юзера, не на общий пул

### 0.3 Где хотелки применяются (сквозная проводка)

1. **Поиск HH**: конфиги (опыт×формат×регион) собираются из хотелок юзера; в daily union-прогоне — группировка по уникальным комбинациям хотелок вместо «одни параметры на всех».
2. **Фильтры**: junk/off-PM — только для PM-профилей; `wish_exclude` — на fan-out.
3. **Скоринг**: промпт DeepSeek получает хотелки (роль/вилка/формат/опыт/исключения) и обязан объяснить матч «почему да/нет» по каждой.
4. **Дайджест/пуши**: время из `digest_time` юзера; плотность и quiet hours уже per-user.
5. **Диагностика (п.1.2/1.3)**: показывает эффект каждой хотелки («с вашей вилкой 250к+ отсекается ~70% карточек»).

### 0.4 Definition of Done персонализации

Юзер А и юзер Б с разными хотелками: разные запросы к HH, разные отфильтрованные ленты, разные промпты скоринга, разное время дайджеста — при одном общем пуле карточек. Ни одна хотелка не применяется к чужой ленте.

## Дорожная карта (ориентир)

**Неделя 1 — «хотелки заданы, юзер понимает свою картину»**
Экран «Мои хотелки» (0.2, поля + сохранение в user_settings) → диагностика 1.2/1.3 с эффектом хотелок → валидация слов 2.1 → честный daily 2.2 → backfill каждые 2–3ч (3.1) → instant-пуши (4.1) → 6.1 (владелец: GitHub) → 5.1 (poller-сборка)

**Неделя 2 — «хотелки работают по всей линии»**
Хотелки в конфиги HH-поиска (0.3.1, группировка union по комбинациям) → хотелки в промпт скоринга + «почему да/нет» (0.3.3) → junk per-user + wish_exclude (2.5/0.3.2) → инкрементальный HH (2.4) → two-stage скоринг (3.2) → онбординг-визард с хотелками (1.1)

**Неделя 3 — «надёжность и деньги»**
5.2–5.5 (healthchecks, логи, монитор, дрель бэкапов) → 3.3–3.4 ($-метрики, автоподсказка порога) → 4.2–4.3 (плотность пушей, дайджест по digest_time юзера)

**Неделя 4 — «аналитика и полировка»**
7.1–7.2 → 1.4–1.5 (empty states, действия в дайджесте) → 2.6–2.8 (Getmatch, text=, дедуп TG) → остатки P2 по способностям.

## Критерии успеха (через месяц)

1. У каждого активного юзера лента растёт **без нажатия «Искать»** (≥ N новых карточек/день при живых источниках).
2. Юзер может одной кнопкой увидеть, **почему** у него мало/много вакансий, и что поправить.
3. Ни одно ключевое слово не отбрасывается молча — всегда видна валидация.
4. Бот отвечает всем во время любого поиска (уже сделано в 1.2.2 — держать тестом).
5. Расход DeepSeek и здоровье пайплайна видны владельцу ежедневно (jh_digest).
6. Non-PM юзер (если появится) получает вакансии своей роли (junk per-user).

## Чего не делаем

Отдельные БД на юзера · глобальные фильтры/порог/опыт hh · отключение источников «на всякий» · коммит секретов · force-push/wipe · рефакторинг bot.py «ради красоты» (только точечный, по ходу фич).
